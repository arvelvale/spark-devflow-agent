# 节点连接与模型运维

## 连接

```powershell
ssh -p 6006 <用户名>@<节点地址>
```

用户名、节点地址、密码都在根目录登录信息表里（不入库）。2026-09-20 已通过 SSH 实测登录，主机名 `gx10-7f06`。

| 公网端口 | 节点内端口 | 用途 |
|---|---|---|
| 6006 | 22 | SSH |
| 7006 | 7000 | 服务映射 |
| 8006 | 8888 | 服务映射 |
| 9006 | 9000 | 服务映射 |

不要修改系统账户、SSH、网络、防火墙、驱动，不重启节点。公共预置模型只读使用；大权重直接在节点下载；长任务用 tmux 托管；磁盘保留至少 20% 空闲；映射到公网的服务必须鉴权。

## 2026-09-24 实测：本地模型与出网

### vLLM + Nemotron 已启动（本地主模型）

tmux 会话 `vllm`，日志 `~/logs/vllm-nemotron.log`，只听 `127.0.0.1:8000`（未映射公网），`served-model-name=nemotron`：

```bash
source ~/envs/vllm/bin/activate && vllm serve ~/models/Nemotron-3.5-Lightning-30B-A3B-NVFP4 \
  --served-model-name nemotron --host 127.0.0.1 --port 8000 \
  --moe-backend marlin --kv-cache-dtype fp8 --enable-prefix-caching \
  --gpu-memory-utilization 0.55 --max-model-len 131072 \
  --mamba-backend flashinfer --mamba-cache-mode align \
  --reasoning-parser nemotron_v3 --tool-call-parser qwen3_coder --enable-auto-tool-choice
```

- 参数取自模型 README 的 DGX Spark 配方，**去掉了 DSpark 投机解码**：草稿模型 `...-NVFP4-DSpark` 不在节点上，节点也访问不了 HF。上下文从默认 1M 限到 128K，显存比例 0.55，给 Ollama 留空间。
- 冷启动约 5 分钟（52 个分片加载 + 125 s 引擎初始化）。KV cache 200 万 token，128K 请求最多并发 15 个。启动时 flashinfer 连 `edge.urm.nvidia.com` 超时只是警告，不影响服务。
- 与 Ollama Qwen 同时加载时，内存已用 70 GiB / 121 GiB。

### 两个本地模型对比（同一节点、同一脚本）

| 项 | vLLM + Nemotron-3.5 30B-A3B NVFP4 | Ollama + Qwen3.8 27B Q4_K_M |
|---|---|---|
| 工具调用（`scripts/toolcall_probe.py`，选工具 + 参数 + 用结果收尾） | 2/2 | 2/2 |
| 工具调用首轮 / 收尾 | 0.6–0.8 s / 1.2–2.3 s | 2.3 s（冷启动 10.5 s）/ 3.0–3.5 s |
| 生成速度（600 token 代码题，两次） | **~80 tok/s** | 11–13 tok/s |

结论：**本地主模型用 vLLM + Nemotron**，Qwen 作为备用。样本只有两道工具题，还不能证明复杂规划质量，任务集评估时再比。

### 节点出网

- 直连：**国内通，境外不通**。StepFun、百度、ModelScope、清华 PyPI 可达；JEV（api.typesafe.ai）、Linear、GitHub、HF、hf-mirror 的 TCP 都连不上（DNS 能解析）。
- 解决办法：**SSH 反向隧道**。`scripts/node.py run` 在节点回环地址上开一个转发（端口由节点分配，多个会话可并行），流量经 SSH 回到操作机的本地代理（`127.0.0.1:10090`）。只有显式设置 `https_proxy` 的进程会走这条路，不改节点任何系统或网络配置。实测 JEV、Linear、GitHub 均可达。
- 代价（要如实写进 README）：agent 调 JEV 和 Linear 时，**操作机必须在线并保持隧道**。StepFun 直连，不受影响。

## 模型安装

目标为 Qwen3.8 27B。官方来源：

- https://huggingface.co/Qwen/Qwen3.8-27B
- https://ollama.com/library/qwen3.8:27b

2026-09-20 已完成可用性验证。节点预装 Ollama 0.33.2，已有 `modelscope.cn/unsloth/Qwen3.8-27B-GGUF:latest`，复用现有权重，创建本地别名 `qwen3.8:27b`。此别名指向 ModelScope 上的 Unsloth 量化包，并不表示重新下载了 Ollama 官方库版本。

- 元数据：基座 `Qwen3.8 27B`，参数量 27,320,697,856，GGUF，Q4_K_M。架构字段 `qwen35` 是格式架构标识，基座名称确认为 Qwen3.8。
- 模型摘要：`95c9635e54b021f5dd0aa39efe97b26ac3c37ac550a3803f557de2f6a9904f74`。
- Ollama 列表显示磁盘体积约 17 GB，实际加载约 16.2 GB；`size_vram` 等于模型加载体积，表示全量 GPU 加载。
- 实测调用本机 `/api/generate`，4096 上下文、关闭思考，询问“17乘以19等于多少”，返回 `323`，`done=true`。首次请求约 8.69 秒，其中加载约 8.07 秒。短输出不作为稳定吞吐基准。
- 模型声明支持视觉、工具、思考；本次仅验收文本推理，其他能力待实测。声明最大上下文 262144，不代表本次已配置或验证该长度。
- 节点访问 `registry.ollama.ai:443` 超时；现有权重已可用，因此无需重复下载。未更改系统服务、驱动、账户或网络配置。

## 使用

SSH 登录后运行：

```bash
ollama run qwen3.8:27b
```

如需从 Windows 应用调用，保持以下 SSH 隧道运行：

```powershell
ssh -N -p 6006 -L 11434:127.0.0.1:11434 <用户名>@<节点地址>
```

应用填写 Ollama 地址 `http://127.0.0.1:11434`，OpenAI 兼容地址 `http://127.0.0.1:11434/v1`，模型 `qwen3.8:27b`。本次未建立持久本地隧道，未验证 OpenAI 兼容接口，不新增公网模型端口。

本地 `scripts/node_admin.py` 从登录表读取凭据，只连接 6006；首次连接记录主机密钥到项目 `.ssh_known_hosts`，后续校验。首次指纹尚未与管理员独立核对。`scripts/verify_model.py` 可通过该工具在远端执行推理验收。

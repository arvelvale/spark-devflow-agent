## 1. 目标与约束

### 1.1 评分项 → 架构应答

| 评分项 | 权重 | 本架构的应答 |
|---|---|---|
| 实用性/落地/创新 | 25% | 解决具体痛点：大技能库选择错误（官方实测误加载 16.8%）、长会话上下文腐烂、记忆无关注入拖慢决策。用 JEV 结构化决策层给出可量化收益 |
| 智能体与模型优化深度 | 25% | 多组件协同（决策层/记忆层/技能层/压缩）+ 模型分工路由 + Skills 渐进式披露 + JEV 问题设计规范 |
| 完整性 | 20% | 前后端完整、评估 harness、文档、可演示降级链路 |
| 平台适配 | 15% | 主推理全量跑在 Spark 本地 Qwen3.8；StepFun 按赛事要求使用；离线整理任务用 tmux 托管 |
| 演示效果 | 10% | 一个场景闭环 + A/B 对照（有/无 JEV 的 token 与成功率差异） |
| 征文 | 5% | 开发历程记录 |

### 1.2 硬约束

- 节点规则：不改系统账户/SSH/网络/防火墙/驱动，不重启节点；磁盘保留 ≥20% 空闲；映射公网的服务必须鉴权；长任务 tmux 托管。
- **外调边界（如实说明）**：JEV 与 StepFun 均为外部调用，流程不是"全离线"，对外表述只能说"主推理本地完成"。
- StepFun 限速：Morning 实测 RPM≈10 阶梯限速，必须指数退避重试 + 本地兜底。
- JEV 限速：250k tok/s、1200 请求/分钟（官方标注会动态调整）；429/529 用 SDK 默认退避。
- 凭据：JEV key 与 StepFun key 只从 `凭证信息存放.md` 读取并注入环境变量（`TYPESAFE_API_KEY` / `STEPFUN_API_KEY`），脚本不落盘、日志不打印。

### 1.3 JEV 能力边界（设计必须绕开的官方已知缺陷）

来自官方 jaggedness 页，全部落到设计约束：

1. **字面阅读**：指令写什么答什么。每个问题写完整条件，边界情况进 criteria。
2. **不算数**：计数、算术、插值全在代码里做；需要"数"就用代码遍历候选逐个问。
3. **日期不可比**：抽取（Choice 闭集）交给 JEV，比较/时长在代码。
4. **间接层数越多越差**：问题直指 state 字段名，少用双重否定。
5. **大 state 混无关内容掉精度**：先代码过滤再送 state；只送该问题需要的字段。
6. **对抗内容**：state 是不可信数据，注入文本可能带偏判断；criteria 写死边界。
7. **指令与 criteria 矛盾会混淆**：criteria 是指令的延伸，两边措辞对齐。
8. **结构不变量不保证**：同一判断的 Noul 与 yes/no Choice 数值不可互换；阈值不跨问题类型移植。
9. **不生成文本**：摘要、生成一律主模型（本地 Qwen）负责，JEV 只做选择与评分。
10. **中文精度低于英文**：instructions 用中文时先在任务集上验 confidence 分布，必要时关键问题双语对照。

**冒烟实测（2026-09-22，一次真实调用）**：官方 quickstart 同款 state，三问（noul/choice/score）合并单请求；英文与中文各一发。两侧 `department` 均选 technical（概率 0.82，confidence 0.73/0.72），`frustration` 均判 1.0–1.05 级（confidence 1.0/0.92），urgency noul 均 0.98。英文 input 420 tok、中文 458 tok，output 各 71 tok。结论：接口形状与文档完全一致，简单样本上中文未见明显偏差；**样本极简单，不能作为精度证据**，任务集验证仍按第 11 节执行。

## 2. 总体架构

```
用户 / CLI / API
      │
      ▼
┌───────────────────────── Agent 内核（单进程 Python） ─────────────────────────┐
│                                                                              │
│  规划循环（主模型 = 本地 Qwen3.8:27b）                                          │
│   目标 → 拆解 → 调用能力 → 观察 → 继续/收敛                                     │
│      │                    │                     │                              │
│      ▼                    ▼                     ▼                              │
│  ┌──────────┐      ┌─────────────┐      ┌──────────────┐                       │
│  │ 决策层   │      │ 能力层      │      │ 记忆层       │                       │
│  │ JEV +    │─────▶│ skills 注册 │      │ 工作/情景/   │                       │
│  │ StepFun  │      │ 工具调度    │      │ 语义/画像    │                       │
│  │ flash    │      │             │      │ (SQLite)     │                       │
│  └──────────┘      └─────────────┘      └──────────────┘                       │
│       │                                                        │               │
│       │ 所有 JEV 调用走统一 DecisionClient                       │               │
│       ▼                                                        ▼               │
│  ┌──────────────────────────────────────────────────────────────────────┐    │
│  │ 模型服务层：本地 Ollama(11434) │ StepFun(step_plan/v1) │ JEV(systemone)│    │
│  └──────────────────────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────────────────────┘
```

职责划分：

| 模块 | 负责什么 | 不负责什么 |
|---|---|---|
| 规划循环 | 目标拆解、工具调用决策、生成回复与摘要 | 一切"选哪个"的结构化判断（交决策层） |
| 决策层（JEV） | 技能选择、记忆选择、压缩分块处置、工具参数确认、置信度门控 | 生成任何自由文本；算术；阈值最终裁定（阈值在代码） |
| 快速决策（StepFun flash） | 意图路由、需要语义理解的快速判断（与 JEV 搭配，见 3.5） | 长程规划、最终回复 |
| 能力层 | 技能索引与按需加载、工具执行与结果截断 | 判断该用哪个 |
| 记忆层 | 分层存储、本地召回、写入门控、离线整理 | 最终精选（JEV Noul 精排后代码定夺） |
| 模型服务层 | 路由、限流退避、失败降级 | 业务逻辑 |

### 2.1 一次完整 turn 的时序

```
1. 输入进内核，写入工作记忆
2. 本地召回：技能索引（一行式）+ 记忆候选（结构化+关键词，无向量库）
3. 决策层一次请求（fan-out）：
   - Choice: 该用哪个技能（含"无匹配"选项）
   - Noul × 3: 本轮是否真的需要技能 / 记忆 / 压缩
   - Score: 各记忆候选相关度（或 Noul 逐个）
4. 代码按 confidence 三档处置：
   - 高 → 直接采用；中 → 降级或追问；低 → 回退本地检索交主模型
5. 技能命中才加载全文进上下文（渐进式披露）
6. 主模型（本地 Qwen）规划：决定工具调用
7. 工具参数：闭集参数 JEV Choice 确认；自由文本参数主模型直接给
8. 代码执行工具（权限分级），结果截断后回填
9. 主模型生成回复
10. 写回：记忆分块 → JEV 入库门控 → SQLite；上下文超水位 → 压缩（第 8 节）
```

## 3. 决策层：JEV + StepFun 快速决策

### 3.1 统一 DecisionClient（所有 JEV 调用的唯一出入口）

- 封装：重试退避（429/529，honor retry-after）、超时、用量日志（input/output tokens 单独记账）、**结果缓存**（key = state+questions 哈希，支持 keyless 重放，官方 cookbook 模式）、降级钩子（抛错即回退本地检索）。
- 模型固定 `jev-latest`（响应里记录实际版本号 `jev-1.13.x`，便于阈值回归）。
- 问题模板集中在一个 `questions.py`，与 jaggedness 清单逐条对齐评审。

### 3.2 问题设计规范（写每个问题前过一遍）

1. 一个判断一个问题；复合判断拆多个问题在代码里加权（composite scoring）。
2. instructions 写完整自然语句，不自作聪明省略；criteria 与 instructions 措辞对齐。
3. 需要引用 state 字段时用反引号路径（如 `` `ticket.messages[0].text` ``）。
4. 同一 state 的问题全部一次请求发完（fan-out，官方实测 13 问合并比 13 次单独调用便宜 12.2 倍、快 10 倍）。
5. 每个问题的阈值独立标定，不在 Noul 与 Choice 间移植。
6. 送 state 前代码先过滤，只留该问题需要的字段。

### 3.3 四个决策点的设计

#### a) 技能选择（第一阶段，对标官方 skill_suggestion，实测误加载 16.8%→7.3%）

两级请求：

- **第一级（宽排）**：state = `{request, recent_context}`；Choice 覆盖技能索引全部条目（criteria = 一行描述）；同时 3 个 gate Noul：
  - `acts_on_user_system`：是否要求操作用户的文件/账号/设备/服务（而非只解释）
  - `would_follow_documented_procedure`：谨慎的专家是否会查既定流程
  - `prose_suffices`：纯 prose 不带工具能否满足（**反向题**，取 1-v）
  - gate = 三者均值；**设计值 gate < 0.30 → 不推荐任何技能**（官方起始值，待实测）。
- **第二级（精排）**：只对 top3 加载完整描述+SKILL.md 开头（各约 700 字符）；Choice 复判 + 每个候选一个 `fits` Noul；**设计值 最高 fits < 0.30 → 全部拒绝**。
- 命中后只往主模型上下文插一行 `<skill_relevance>`，技能全文按需加载——** roster 文本保持不变以保留前缀缓存**。
- 允许多技能（turn 需要组合时Choice 给多选语义由代码拆解）与无匹配（两级都可空手归）。

#### b) 记忆选择

- 本地召回候选（结构化过滤+关键词/实体匹配，不上向量库）。
- 每个候选一个 `relevant` Noul（"这段记忆对完成当前目标是否有用"），一次请求全部问完。
- 代码按阈值切分：≥0.7 直接进上下文；0.4–0.7 进摘要位；<0.4 丢弃（**设计值，待实测**）。
- confidence 低或 JEV 不可用 → 回退纯关键词排序，交主模型自行判断。

#### c) 上下文压缩

见第 8 节（独立成节因为它是评分项里"上下文管理"的直接证据）。

#### d) 工具调用门控

- 函数名：若工具集是闭集，用 Choice（criteria 写每个工具的适用场景）；参数枚举值用 Choice；数值/时间参数主模型给、代码校验。
- **权限分级 × confidence 双阈值**（对标官方 confidence-routing）：

| 工具权限 | confidence 要求（设计值） | 低于阈值的行为 |
|---|---|---|
| 只读（查文件、搜索） | ≥0.6 直接执行 | 让主模型重述参数再试一次 |
| 本地写（写文件、改记忆） | ≥0.8 执行 | 向用户确认 |
| 网络/不可逆操作 | ≥0.9 执行 | 拒绝执行并解释 |

- 阈值语义复述（防"90%减伤被写成 damage*0.9"类事故）：这里是"置信度达到才免确认执行"，不是成功率；标定方法见第 12 节。

### 3.4 JEV 不可用的回退链路（必须可演示）

JEV 超时/429 用尽/无 key → DecisionClient 抛 `DecisionUnavailable` → 各决策点降级：

- 技能选择 → 技能索引直接进主模型上下文，让它自己选（基线行为）。
- 记忆选择 → 关键词排序 top-k。
- 压缩 → 纯代码规则（保护清单 + 最近 N 轮 + 超龄轮次丢弃）。
- 演示时主动展示这条链路，作为"依赖外部服务也不瘫"的证据。

### 3.5 StepFun flash 的职责边界

- 用途：**意图路由**（官方 intent-routing 模式：用户输入 → 分类 → 路由到 确定性逻辑/本地 Qwen/人工），以及与 JEV 搭配的快速语义判断（如"这两段是不是同一件事"这类 JEV 不便做的模糊匹配的先筛）。
- 不用它做：最终回复生成、长程规划、摘要（这些在本地 Qwen，省 RPM 也保隐私）。
- RPM≈10 的应对：调用排队 + 指数退避 + 失败即走本地 Qwen；一个 turn 内 StepFun 调用 ≤2 次（设计约束）。

## 4. 模型服务层与路由

| 任务 | 模型 | 说明 |
|---|---|---|
| 规划/工具决策/生成/摘要 | 本地 Qwen3.8:27b（Ollama 11434，OpenAI 兼容 `/v1`） | 已验证；全量 GPU 加载 |
| 意图路由、快速语义判断 | StepFun `step-3.7-flash` | 待模型名核实；每 turn ≤2 次调用 |
| 技能/记忆/压缩/参数的结构化决策 | JEV `jev-latest` | 统一 DecisionClient |
| 离线整理（做梦） | 本地 Qwen3.8 + tmux | 每日低峰跑 |

隐私开关：用户可标记会话/记忆深度为"不出节点"，此类内容绝不进 StepFun/JEV 的 state（默认深度定义见第 5 节）。

## 5. 记忆层

### 5.1 分层结构（SQLite，JSON 列起步，不上向量库）

| 层 | 内容 | 生命周期 |
|---|---|---|
| 工作记忆 | 当前 turn 的目标、约束、未完成事项、工具结果 | 随 turn 结束归档 |
| 情景记忆 | 发生过的事件（请求、执行、结果） | 衰减管理，可归档 |
| 语义记忆 | 从事件提炼的事实与偏好 | 冲突消解后长期 |
| 画像 | 用户稳定偏好（称呼、语言、审慎级别） | 长期，用户可审阅可删 |

借鉴 Morning 双轴：`layer` × `kind`，深度轴 `surface/personal/vulnerable/core`。**深度 ≥ personal 的记忆默认 privacy=local，不进任何外部调用的 state**（如实边界：深度是用户可见软标签，不是安全边界，真正边界是代码里的路由白名单）。

### 5.2 存取管线

- **写入门控**：候选记忆分块后，JEV Noul"这条值得长期记住吗"+ Choice 归层；不确定的进"待确认区"由用户审阅（不强行决定）。
- **回忆**：本地结构化召回 → JEV Noul 相关度精选 → 代码按 3.3b 阈值入上下文。
- **整理（离线）**：tmux 托管每日任务：聚类（实体+kind 二级分组）→ 下沉提炼（本地 Qwen）→ 新鲜度衰减 → 冲突消解 → 生成候选；与实时路径完全分离。

### 5.3 第一阶段最小实现

工作记忆 + 情景记忆两层、关键词召回、JEV 相关度精选。画像与做梦整理放第二阶段——先用最小闭环验证"记忆选择"的收益，再扩。

## 6. Skills 层

- **注册表**：每个技能 = `name / 一行描述 / 触发条件 / 输入输出契约 / 权限级别（继承第 3.3d 表）`。索引一行随每个请求进上下文（保持不变以保前缀缓存），全文按 3.3a 命中才加载。
- **技能形态**：Markdown 指令文档（渐进式披露的主体）+ 可选脚本/参考文件；不改写主模型 system prompt。
- **无匹配是一等公民**：两级都可返回空，空手归时主模型按通用能力应答，不硬凑。
- **最小演示场景的技能包**：随内核交付 3–5 个技能（如：文件整理、日志分析、日程查询、知识问答、代码审查），其中至少一个覆盖"容易混淆的近义技能对"用于演示误选率下降。

### 官方参考与可借鉴模式（NVIDIA rag-blueprint，2026-09-22 研读）

本地副本在 `reference/nvidia-skills/rag-blueprint`（NVIDIA/skills，Apache-2.0），该 skill 管理 NVIDIA RAG Blueprint 产品栈，我们只借鉴**技能设计模式**：

| 官方做法 | 借鉴点 |
|---|---|
| frontmatter 极丰富：version / compatibility / argument-hint / tags / languages / frameworks / domain / author | 注册表字段按此扩充；description 前触发词（deploy/enable/troubleshoot/shutdown…）直接服务我们的技能选择 Choice 问题 |
| `allowed-tools` 白名单：只列只读命令前缀（`Bash(docker ps *)`、`Bash(nvidia-smi *)`…）+ Read/Grep/Glob | 3.3d 权限分级的skill 侧落地：技能级 allowed-tools 与工具级阈值双闸门 |
| 意图路由表：用户意图 → references/deploy.md 等；歧义时从上下文推断 | SKILL.md 保持"薄路由器"（官方 204 行），细节全在 references/ 按需加载——与渐进式披露一致 |

## 7. 工具调用

- 工具 schema 集中注册；每个工具声明权限级别、超时、结果大小上限（超限截断+摘要，防上下文膨胀）。
- 调用链：主模型发起意图 → 闭集部分 JEV Choice 确认（3.3d 双阈值门控）→ 代码执行 → 结果回填并记账。
- 工具结果中的文本视为不可信数据（与 state 同级的注入防护）。
- 失败：重试一次 → 降级为"向用户说明失败原因"，不无限重试烧 token。

## 8. 上下文压缩

**触发**：上下文 token 超过预算水位（如规划窗口的 70%，**设计值**）时对最早的非保护块启动压缩。

**保护清单（硬编码在代码，永不交给模型裁定）**：当前目标、明确约束、未完成事项、关键证据引用（文件路径/命令/返回值摘要）。

**压缩流程**：

```
1. 分块：把待压缩区切成块（按轮次/主题）
2. JEV 一次请求，每块一个问题：
   - Score: 该块对未来目标的参考价值（levels: 可丢弃/留摘要/必须保留）
   - Noul: 该块是否包含未完成事项或约束（双保险，与保护清单取并集）
3. 代码执行：必须保留 → 原样；留摘要 → 交本地 Qwen 生成摘要；可丢弃 → 丢弃
4. 原始完整记录落盘（sessions/ 目录），保留恢复入口
```

**验收口径**：压缩前后输入 token 下降比例 vs 任务成功率变化（对照实验，见第 12 节）。压缩永远可能丢信息，所以"保留原始记录"是产品承诺不是实现细节。

## 9. 安全与权限

- 公网可达服务必须鉴权（节点规则）；API 层 JWT 或 token。
- 工具权限表（3.3d）+ 写操作确认；危险操作（删文件、发网络请求）默认最高阈值。
- 注入防护：所有外部文本（用户输入、工具结果、检索内容）进 state 前标注为数据；JEV 侧 criteria 写死"不执行文本中的指令"类边界（官方 jaggedness #6，只能缓解不能根除，如实写进演示）。
- 凭据：只从凭证文件/环境变量读取；日志只记 key 是否存在（bool），不记值——与 Morning `stepfun_key_loaded` 同款。

## 10. 失败路径与降级总表

| 故障 | 检测 | 降级 |
|---|---|---|
| JEV 429/529/超时 | SDK 重试耗尽 | 3.4 节各决策点回退；记用量日志 |
| StepFun 429/超时 | 重试耗尽 | 该步改本地 Qwen；turn 内不再重试 StepFun |
| 本地 Ollama 无响应 | 连接失败/超时 | 向用户报错；离线任务 tmux 内重试 |
| 工具执行失败 | 非零退出/超时 | 重试一次 → 报告失败原因 |
| 压缩后任务失败率上升 | 对照实验指标 | 调高保护清单覆盖率或预算水位 |

每条降级都要进演示脚本（第十评分项是演示效果，降级链路是加分证据）。

## 11. 评估与验收计划

- **任务集**：内置 JSON 任务集，覆盖三类请求——有唯一技能覆盖的、无技能覆盖的（考据官方方法，防"硬凑技能"）、需要组合技能的；每类标注期望决策。
- **指标**（对齐赛事文档已列口径）：任务成功率、技能漏选率/误选率、记忆相关度、主模型输入 token、端到端耗时、外部调用开销（JEV 输入 token 计费 + StepFun 调用次数）。
- **A/B harness**：同一任务集跑"有 JEV 决策层"与"无 JEV（主模型自选）"两臂，输出对照表——这是演示和征文的核心数据。
- **阈值标定**：confidence 阈值从保守值起步，在任务集上画 PR 曲线后定值；每次 JEV 版本变更（响应 `model` 字段变化）重跑标定。

## 13. 未决问题与风险

1. `step-3.7-flash` 模型名待核实（Morning 实测环境是 `step-3.5-flash`）。
2. 组委会对"外部 API 调用"的规则截图未含完整规则；用户已确认有 key 可用，**提交前需再确认组委会口径**，避免演示时被质疑数据出境。
3. JEV 中文精度：冒烟测试（2026-09-22，简单样本）中英文决策一致、confidence 略低；任务集级验证未做。
4. JEV 限速官方标注"动态调整"，高峰期 429 处理需常备。
5. 速率计费：JEV 按输入 token 计费，任务集每轮全量 fan-out 的开销需在 harness 里单独记账，防止评估本身烧钱。
6. 压缩可能丢信息——"保留原始记录可恢复"必须落实为文件和 UI 入口，不能只写进文档。

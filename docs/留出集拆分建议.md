# 留出集拆分建议

> 本文档记录技能选择任务集（60 条）的训练集/留出集拆分方案。
> 目的：防止阈值调优过拟合，让最终验收结果有泛化参考价值。

## 一、背景

当前 60 条任务的阈值（skill_gate / skill_none / skill_fit 等）都是在同一批数据上调优的。直接用同批数据验收会高估泛化能力。

**正确做法**：阈值调优只用训练集；留出集只在最终验收时跑一次，结果不回填到调优过程。

## 二、拆分原则

1. 训练集每技能 ≥ 3 条：保证每个技能有足够正例
2. 留出集侧重边界 case：模糊场景（none 类）、附带动作题、上下文依赖题
3. 近义组不两边都放：同一互补对里，训练集和留出集各留一边
4. multi 类全留训练集：组合技能需要足够训练样本
5. 留出集 implement-change ≤ 2 条：避免单技能占比过高

## 三、拆分比例

- **训练集 42 条** : **留出集 18 条**（约 7:3）
- 留出集 = 11 条 none + 7 条 single
- multi 3 条全留训练集

## 七、存储方式

**新建独立文件** `eval/tasks/skill-selection-heldout-v1.json`，格式与 v1 完全一致。

**不在现有文件里加 split 字段**：接口 2 已冻结 v1（2026-09-24 晨熠确认），"只增不改"指只能增条目、不能加字段。

## 八、给队长/评估负责人的行动项

| 事项 | 负责人 | 说明 |
|---|---|---|
| 建 skill-selection-heldout-v1.json | 评估负责人 | 按第四节清单填入 18 条 |
| 确认拆分合理性 | 队长 + 晨熠 | 检查是否有训练集覆盖不足的技能 |
| run_selection.py 加 --split 参数 | 评估负责人 | 读两个文件分别跑分，输出对比报告 |
| 防泄漏纪律 | 全体 | 留出集结果在最终验收前不公开 |

## 九、防泄漏纪律

| 阶段 | 留出集可见性 |
|---|---|
| 阈值调优中 | ❌ 不可见（包括评估负责人） |
| 调优完成、等待验收 | ❌ 仍不可见 |
| 最终验收时 | ✅ 跑一次，结果同步全体 |
| 验收后迭代 | 如需调阈值，回到训练集；留出集重新封闭 |

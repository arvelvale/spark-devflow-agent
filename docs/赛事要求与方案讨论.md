## 当前讨论方向（未定案）

用户希望在 agent 主体中引入 JEV，辅助 skills 选择、上下文压缩和记忆选择。具体业务场景尚未确定。

- Spark 上的主模型负责规划、工具执行决策与文本生成；JEV 负责结构化选择和评分，程序负责预算、权限与回退。
- JEV 不生成自由文本：可以决定片段如何处理，摘要仍由主模型生成。
- 先本地召回候选技能和记忆，再交给 JEV 判断；允许多个技能以及无匹配结果。
- 压缩时保护当前目标、明确约束、未完成事项及关键证据引用；保留原始记录以便恢复。
- JEV 不确定或不可用时回退到本地检索与主模型。外部调用意味着不能未经说明就宣称全流程离线或数据完全不出节点。
- 建议实施顺序：技能选择 → 记忆选择 → 上下文压缩；用任务成功率、漏选/误选、输入 token、整体耗时和调用开销对照验证。
- confidence 是分布派生指标，不能直接视为本任务的正确率；阈值待任务集实测。

## 按评分标准提出的建议（非已决定架构）

优先完成一个具体场景的可演示闭环，再展示 JEV 调度与上下文管理的收益。通用 agent 框架本身不足以证明行业价值。平台适配虽单列 15%，平台优势也出现在首项，不能只把 Spark 当作与作品无关的运行地点。

NVIDIA 入门按用途理解：

| 组件 | 用途 | 本项目建议 |
|---|---|---|
| CUDA | GPU 计算基础平台 | 理解其与驱动、推理框架的关系即可；初期无需编写 CUDA 内核或改动节点环境。 |
| TensorRT-LLM | 优化 NVIDIA GPU 上的大模型推理 | 出现实际推理瓶颈后再评估；模型架构、量化格式及 Spark 支持均须核实。 |
| NIM | 封装模型推理服务，提供标准接口 | 可选部署途径；不是 agent 框架，也不应假设任意模型均适配 Spark。 |
| NeMo Agent Toolkit | 对 agent 工作流做集成、评估及性能剖析 | 优先做小规模兼容性验证，尝试用于比较有无 JEV 的 token 与延迟。 |
| DGX Spark Playbooks | 官方任务实践指南 | 作为选定任务的配置与操作参考，仍须遵守赛事节点限制。 |

第一阶段沿用已验证的本地模型服务作为基线，不为罗列技术名词同时切换多套推理框架。StepFun 要求确认后再明确模型分工。多智能体和微调只有解决具体问题、能给出评估证据时再引入。

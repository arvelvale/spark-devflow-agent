# 接口 2：任务集格式（`eval/tasks/*.json`）

状态：**草案 v1（2026-09-24）**。代码侧校验在 `eval/taskset.py`，跑分入口 `python -m eval.run_selection`。

任务集用来回答一个问题：**有 JEV 决策层和没有（主模型自己选）相比，哪边选技能选得更准、更省**。它也是 skills 优化和提示词优化两位同学迭代时的回归测试。

## 文件结构

```json
{
  "version": 1,
  "name": "skill-selection-v1",
  "description": "开发流技能选择基础集：单技能、无技能、需组合三类",
  "tasks": [
    {
      "id": "sel-001",
      "category": "single",
      "input": "把今天改的几个提交整理一下，落到 docs/progress 里",
      "context": [],
      "expect": {
        "skills": ["progress-logger"],
        "confusable": ["standup-brief"],
        "tier": "local"
      },
      "tags": ["近义对"],
      "note": "关键词是'落到文件'，站会简报不落文件"
    }
  ]
}
```

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | 是 | 格式版本，目前固定 1 |
| `name` | 是 | 任务集名，出现在报告标题里 |
| `tasks[].id` | 是 | 集内唯一，建议 `sel-001` 递增，删除的编号不复用 |
| `tasks[].category` | 是 | `single`（恰好一个技能）/ `none`（不该用任何技能）/ `multi`（需要组合多个技能） |
| `tasks[].input` | 是 | 用户原话，照真实口吻写，别写成技能描述的同义改写 |
| `tasks[].context` | 否 | 之前几轮对话，`[{"role": "user"/"assistant", "content": "..."}]`，用来测依赖上下文的请求（如"那就按这个拆吧"） |
| `tasks[].expect.skills` | 是 | 期望选中的技能名列表。`none` 类必须为 `[]`；`single` 恰好 1 个；`multi` ≥ 2 个 |
| `tasks[].expect.confusable` | 否 | 容易误选成的技能，报告会单独统计"近义对混淆" |
| `tasks[].expect.tier` | 否 | 期望路由：`local` / `cloud`，给 agent 优化同学标定路由阈值用 |
| `tasks[].tags` | 否 | 自由标签，报告按标签分组 |
| `tasks[].note` | 否 | 为什么这么标，给后来的人看 |

## 指标（`eval/run_selection.py` 计算）

以下"选中"都指 agent 最终加载的技能集合 S，期望集合为 E：

| 指标 | 定义 | 方向 |
|---|---|---|
| 完全正确率 | S == E 的任务占比 | 越高越好 |
| 漏选率 | E 非空且 E ⊄ S 的任务占比（分母：E 非空的任务） | 越低越好 |
| 误选率 | S 中含有不在 E 里的技能的任务占比（分母：全部任务） | 越低越好 |
| 硬凑率 | E 为空但 S 非空的任务占比（分母：none 类任务） | 越低越好 |
| 近义混淆 | 选中了 `confusable` 里的技能的次数 | 越低越好 |
| 路由一致率 | 有 `tier` 标注的任务里，实际路由 == 期望的占比 | 越高越好 |
| 开销 | JEV 输入/输出 token、主模型 token、平均耗时 | 越低越好 |

## 写任务的约定

1. 三类比例建议 single : none : multi ≈ 6 : 3 : 1。none 类不能少，它测的是"不硬凑技能"（官方 skill_suggestion 方法的核心）。
2. 每组近义技能对（如 progress-logger / standup-brief）至少 4 条，两边各 2 条。
3. 一条任务只测一件事。拿不准该标什么的，写进 `note`，不要硬标。
4. 新增技能时同时加它的 triggers 对应任务，以及至少 1 条 not-for 对应任务。

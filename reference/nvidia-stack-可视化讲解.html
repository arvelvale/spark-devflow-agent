五个关键概念，各配一张剖面图

CUDA 是地基，NeMo 是车间，NIM 是集装箱，vLLM 和 OpenShell 是本次节点检查后新晋重要的两位。

我们的用法：不写内核，只看懂依赖关系。Ollama 已在通过 CUDA 调 GPU。

形态：纯 Python，可指向本地 Ollama。

NIM L4 · 集装箱
类比：把模型装进标准集装箱——模型 + 引擎 + API + 依赖打成一个容器

好处：标准化、可移植、企业级验证。官方基准：Llama 3.1 8B 单卡 H100，开启比不开启吞吐约 2 倍（1201 vs 613 tok/s）。

注意：研发/演示免费，生产需 NVIDIA AI Enterprise 许可；需 NGC 拉镜像，GB10 aarch64 兼容性未验证。

节点现状：~/envs/vllm 已装 vllm 0.28.0 + torch 2.13.0 + triton 3.7.1 + flashinfer，暴露 OpenAI 兼容 API（:8000）；配套权重 ~/models/Nemotron-3.5-Lightning-30B-A3B-NVFP4（21G）就位；~/tw 还有 197 个离线 wheel 可重建环境。

我们的决策：「平台推理优化」演示的第一候选——激活即用，零安装。

OpenShell L6 · 沙箱（新晋）
类比：给 agent 建的安检隔离区——能力不关禁闭，但每一道门都有人查
文件 · Landlock 只放行白名单 网络 · 默认全部拒绝 凭据 · provider 统一注入 推理 · 拦截并路由本地
Agent跑在沙箱里
⇄
ToolsCLI / MCP
→ 只有这一条
inference.local → 本地 vLLM

它防四类风险：数据泄露、恶意代码执行、误操作、提示注入。策略写在 YAML 里可版本控制、可审计。

形态与出处：开源，Docker 内跑 k3s，官方 playbook 明确支持 DGX Spark。对应我们架构文档第 9 节——工具权限分级的可选加固路径。

03 / 定位

我们的请求走哪条路

虚线 = 我们跳过的层。单节点单模型规模下，跳过是合理选择，不是将就。

基线（已验证在跑）
请求→ Agent 内核→ Ollama :11434→ Qwen3.8 27B→ CUDA→ GB10
实测：4096 上下文，「17×19」答 323，首请求 8.69s（加载 8.07s）。JEV / StepFun 走外部分支，不占本地路径。
二档候选（现成资产，待验证）
请求→ Agent 内核→ vLLM :8000→ Nemotron 30B-A3B NVFP4→ CUDA→ GB10
同一份 Qwen GGUF 也可喂给 vLLM（需先转 HF 格式）。NIM / TensorRT-LLM 排在其后：要拉镜像、要转权重，成本高。
英伟达全栈参考形态（仅作对照）
请求→ NIM 微服务→ Dynamo 编排→ TensorRT-LLM→ CUDA→ GB10
Dynamo 官方原话：「单模型单 GPU，推理引擎本身就够了」——这张图是数据中心叙事，不是我们的作业。
